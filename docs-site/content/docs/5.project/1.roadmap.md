## Where the SDK stands

`@circle-rd/auth-ai` is at version `0.1.0`, not yet published to npm. The public API is not stable: while the major version is `0`, a breaking change bumps the minor version. The surface that exists today is described in the [Reference](/docs/reference/configuration): the OIDC relying party, the backend-for-frontend handlers, the Fastify adapter, the browser client with React and Vue bindings, Bearer verification, back-channel logout, the wallet and gateway clients, and the machine API for billing and consumption.

## Planned

| Item | Why |
| --- | --- |
| **Python port** | The CIRCLE stack has Python backends. The port reproduces the same behaviours, which the TypeScript test suite pins (error codes, refresh serialisation, callback failure policy, logout token validation…). |
| **Migration of `gine`** | Move the [gine](https://github.com/circle-rd/gine) application onto the SDK, as a real-world check of the API before it stabilises. |
| **npm Trusted Publishing** | Once the first release is out, replace the `NPM_TOKEN` repository secret used by the publishing workflows with OIDC-based trusted publishing. Releases already carry npm provenance. |
| **More adapters** | Thin adapters on top of the Web-standard handlers, as needs appear. Today only Fastify has one; the [other frameworks](/docs/guides/backend/other-frameworks) guide shows the bridge to write for the rest, and there is no Next.js adapter yet. |

## Not planned here

The SDK has no debit API, by design: the LiteLLM gateway debits the wallet after each call. See [Credit wallet and LiteLLM gateway](/docs/concepts/wallet-and-gateway).

To suggest or discuss a feature, open an issue on [GitHub](https://github.com/circle-rd/auth-ai/issues).
