title: Production checklist
description: "What to change before the first real user signs in: stores, locks, secrets, URLs, logout, logging and dependencies."
---

The quick start and the example app use in-memory stores so that they run with no setup. Work through this list before deploying.

## Storage

- [ ] **`SessionStore` on your database.** `MemorySessionStore` loses every session on restart and cannot be shared. Index `userId` and the provider session id, and purge expired rows. See [Implement the stores](/docs/guides/backend/custom-stores).
- [ ] **`GrantStore` on your database, encrypted at rest.** It holds one long-lived refresh token per user.
- [ ] **A distributed `GrantLock`** when you run several replicas, so two replicas never rotate the same grant at once. The default lock only covers one process.
- [ ] **A shared `ReplayStore`** when you run several replicas (for example Redis `SET NX PX`), so a logout token replayed on another instance is refused.

## Secrets

- [ ] **Cookie secret of at least 32 random characters** (`openssl rand -base64 48`), from your secret manager or environment. Shorter secrets are refused with `CFG_001`. Rotating it only invalidates sign-ins in progress: the session cookie is an opaque random id and is not sealed with it.
- [ ] **Client secret** from the environment. Without `clientSecret` the SDK acts as a public client and the machine API is unavailable, so fail at startup on a missing variable rather than passing `undefined`.
- [ ] Nothing secret in source control, logs or error responses.

## URLs and registration

- [ ] **`redirectUri` is `<origin><basePath>/callback`**, over HTTPS, and registered identically in auth-service. `createAuthHandlers` refuses a mismatch.
- [ ] **`postLogoutRedirectUri`** is registered if you set it.
- [ ] **Back-channel logout URI** `<origin><basePath>/backchannel-logout` is registered in auth-service: HTTPS and reachable **from auth-service**. auth-service waits for these deliveries when a user signs out, so keep the endpoint fast.
- [ ] **End-session or the back-channel URI is enabled**, so the ID token carries `sid`. Keep `requireProviderSession` at its default (`true`).
- [ ] **LiteLLM support** is on and `gatewayUrl` matches the gateway URL exactly (no trailing slash), when you use the gateway.
- [ ] **Machine scopes** `billing:read`, `consumption:read`, `consumption:write` are granted, when you use the machine API.
- [ ] Your reverse proxy forwards the `/auth/*` paths, the `Cookie`, `Origin` and `Sec-Fetch-Site` headers and the request body of the back-channel route unchanged, and terminates TLS (consider HSTS).

## Application behaviour

- [ ] **Entitlements are enforced on the server**, in each route, not only hidden in the UI.
- [ ] **Your own `POST`, `PUT`, `PATCH` and `DELETE` routes check `Origin`**, as the SDK does for `/auth/logout`.
- [ ] **The back-channel route stays outside session and CSRF protection**: it is called without cookies.
- [ ] **`onSessionsEnded`** closes sockets or drops caches of the users whose sessions ended.
- [ ] Tune **`sessionTtlSeconds`** (8 hours by default) and **`claimsRenewSeconds`** (15 minutes by default) to how quickly role and plan changes must reach users.

## Logging and errors

- [ ] **`onError` is set** and logs `error.toJSON()` for `AuthAiError`s: it is the only place the real cause of a failed sign-in appears.
- [ ] **Query strings are not logged**: the callback URL carries the authorization code.
- [ ] **Responses use `toPublicJSON()`**, never `message` or `details`.

## Dependencies and runtime

- [ ] **Node.js 22 or later.**
- [ ] **`fastify` 5.12.6 or later** if you use the Fastify adapter: several 2026 advisories are fixed there.
- [ ] Server clocks are synchronised (token verification allows `clockToleranceSeconds`, 5 by default).
- [ ] Dependency audit in CI (`pnpm audit --prod`).

## Verify end to end

Run the [example app](/docs/guides/operations/example-app) against your auth-service and click **Self-test**: it exercises sign-in, claims renewal, per-audience tokens, introspection, the wallet, the gateway, billing and consumption, and writes a report free of any token or secret to the server log.
